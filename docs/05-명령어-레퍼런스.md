# 명령어 레퍼런스 (29개 전체)

## 핵심 워크플로우 (8개)

### `/gsd:new-project [--auto]`
**목적**: 새 프로젝트 초기화
**흐름**: 질문 수집 → 연구(선택) → PROJECT.md → REQUIREMENTS.md → ROADMAP.md → config.json → STATE.md
**옵션**: `--auto` - 최소 질문으로 자동 진행
**워크플로우 파일**: `workflows/new-project.md` (958줄)

### `/gsd:discuss-phase [N]`
**목적**: 계획 전에 사용자 결정 사항 캡처
**흐름**: 사용자와 대화 → CONTEXT.md 생성 (잠긴 결정 + 보류된 아이디어)
**워크플로우 파일**: `workflows/discuss-phase.md` (227줄)

### `/gsd:plan-phase [N]`
**목적**: Phase의 세부 실행 계획 수립
**흐름**: 연구 → PLAN.md 생성 → 계획 검증 → RESEARCH.md
**에이전트**: phase-researcher → planner → plan-checker
**워크플로우 파일**: `workflows/plan-phase.md` (376줄)

### `/gsd:execute-phase <N>`
**목적**: 계획에 따라 코드 작성 및 커밋
**흐름**: Plan별 Task 순차 실행 → 작업별 커밋 → SUMMARY.md → STATE.md 업데이트
**에이전트**: executor (Plan별 독립 에이전트)
**워크플로우 파일**: `workflows/execute-phase.md`

### `/gsd:verify-work [N]`
**목적**: 결과물이 Phase 목표를 달성했는지 검증
**흐름**: Goal-Backward Verification → VERIFICATION.md → Gap 발견 시 수정 Plan 생성
**에이전트**: verifier
**워크플로우 파일**: `workflows/verify-work.md` (570줄)

### `/gsd:audit-milestone`
**목적**: 마일스톤이 Definition of Done을 달성했는지 검증

### `/gsd:complete-milestone`
**목적**: 마일스톤 아카이브 및 릴리스 태그
**흐름**: 검증 → 아카이브 → MILESTONES.md → Git 태그
**워크플로우 파일**: `workflows/complete-milestone.md` (493줄)

### `/gsd:new-milestone [name]`
**목적**: 다음 버전/마일스톤 시작
**흐름**: 이전 마일스톤 참조 → 새 요구사항 수집 → ROADMAP.md 갱신
**워크플로우 파일**: `workflows/new-milestone.md` (373줄)

## 명령어 → 워크플로우 → 에이전트 매핑

```
명령어 (commands/gsd/)
    │
    │  트리거
    ▼
워크플로우 (get-shit-done/workflows/)
    │
    │  에이전트 생성
    ▼
에이전트 (agents/)
    │
    │  참조
    ▼
레퍼런스 (get-shit-done/references/)
    │
    │  사용
    ▼
템플릿 (get-shit-done/templates/)
```

각 명령어는:
1. `commands/gsd/` 에 .md 파일로 정의됨
2. 해당 워크플로우를 `workflows/` 에서 실행
3. 워크플로우가 필요한 에이전트를 `agents/` 에서 생성
4. 에이전트가 `references/` 의 가이드를 참조
5. `templates/` 의 템플릿으로 결과물 생성
