# 데이터 흐름 & 상태 관리

## 프로젝트 상태 저장소: `.planning/` 디렉토리

모든 프로젝트 상태는 `.planning/` 디렉토리에 마크다운 + JSON 파일로 저장된다.
데이터베이스 없이 **파일 시스템이 곧 데이터베이스**이다.

```
.planning/
├── config.json          ← 워크플로우 설정
├── PROJECT.md           ← 프로젝트 정의
├── REQUIREMENTS.md      ← 요구사항 (v1/v2/out-of-scope)
├── ROADMAP.md           ← Phase 구조
├── STATE.md             ← 현재 상태 (Single Source of Truth)
├── MILESTONES.md        ← 완료된 마일스톤 기록
├── .continue-here.md    ← 세션 핸드오프
├── research/            ← 연구 결과
│   ├── STACK.md
│   └── DOMAIN.md
├── todos/
│   └── pending/         ← 캡처된 아이디어
├── phases/
│   ├── 01/              ← Phase 1 산출물
│   │   ├── PLAN-01.md
│   │   ├── PLAN-02.md
│   │   ├── SUMMARY-01.md
│   │   ├── SUMMARY-02.md
│   │   ├── RESEARCH.md
│   │   ├── CONTEXT.md
│   │   ├── UAT.md
│   │   └── VERIFICATION.md
│   ├── 02/              ← Phase 2 산출물
│   └── .../
└── archive/             ← 완료된 마일스톤 아카이브
```

## 핵심 문서 라이프사이클

### 1. PROJECT.md (프로젝트 정의서)

**생성**: `/gsd:new-project`
**갱신**: 매 Phase 전환 시

```markdown
# 프로젝트 이름

## What is this?
이 제품이 무엇인지 2-3문장 (전문용어 없이)

## Core Value
이 제품이 제공하는 단 하나의 핵심 가치

## Requirements Status
- v1: [진행률] (x/y 완료)
- v2: 계획됨
- Out of scope: n개 항목

## Constraints
- 기술적 제약
- 비즈니스 제약

## Key Decisions
| 날짜 | 결정 | 이유 |
|------|------|------|
| 2024-01-15 | Next.js 사용 | SSR 필요, 팀 경험 |
```

### 2. REQUIREMENTS.md (요구사항)

```markdown
# Requirements

## v1 (Must Have - 첫 릴리스)
- [ ] 사용자 회원가입/로그인
- [ ] 프로필 관리
- [x] 대시보드 ← 완료됨

## v2 (Future)
- [ ] 소셜 로그인 (Google, GitHub)
- [ ] 2FA

## Out of Scope
- 모바일 앱 (이유: v1은 웹만 집중)
- 다국어 지원 (이유: 초기 시장은 한국)
```

### 3. ROADMAP.md (로드맵)

```markdown
# Roadmap

## Phase 1: 기본 인증 시스템
- [x] 완료
- 목표: 사용자가 가입하고 로그인할 수 있다

## Phase 1.1: 이메일 인증 (삽입됨)
- [ ] 진행중
- 목표: 이메일 인증으로 가짜 계정 방지

## Phase 2: 대시보드
- [ ] 대기
- 목표: 사용자가 핵심 데이터를 한눈에 볼 수 있다

## Phase 2.1: 데이터 시각화
- [ ] 대기
- 목표: 차트와 그래프로 트렌드 파악
```

**Decimal Phase Numbering**: Phase 사이에 새로운 Phase를 삽입할 수 있다.
- Phase 1과 2 사이에 긴급한 작업? → Phase 1.1 삽입
- 전체 번호를 다시 매기지 않아도 됨

### 4. STATE.md (상태 - Single Source of Truth)

```markdown
# State

## Current Position
- milestone: v1
- phase: 3 of 7
- plan: 2 of 3
- task: 1 of 3

## Performance
- velocity: 2.5 plans/session
- total_commits: 47
- total_phases_completed: 2

## Session
- last_active: 2024-01-15T14:30:00Z
- current_branch: phase-3

## Accumulated Decisions
| Decision | Rationale | Phase |
|----------|-----------|-------|
| PostgreSQL | 관계형 데이터, ACID 필요 | 1 |
| Tailwind CSS | 일관된 스타일링, DX | 2 |

## Active Blockers
(현재 없음)
```

## config.json (설정)

```json
{
  "mode": "interactive",
  "depth": "standard",
  "profile": "balanced",
  "workflow": {
    "research": true,
    "plan_check": true,
    "verifier": true
  },
  "parallelization": {
    "enabled": true,
    "max_concurrent_agents": 3,
    "min_plans_for_parallel": 2
  },
  "git": {
    "branching_strategy": "phase",
    "commit_style": "conventional"
  }
}
```

### 설정 옵션 설명

| 키 | 값 | 설명 |
|----|-----|------|
| `mode` | `interactive` / `yolo` | interactive: 매 단계 확인, yolo: 자동 진행 |
| `depth` | `quick` / `standard` / `comprehensive` | 연구/계획 깊이 |
| `profile` | `quality` / `balanced` / `budget` | 모델 선택 프로파일 |
| `workflow.research` | boolean | Phase 연구 수행 여부 |
| `workflow.plan_check` | boolean | 계획 사전 검증 여부 |
| `workflow.verifier` | boolean | 결과 검증 수행 여부 |
| `parallelization.enabled` | boolean | 병렬 실행 여부 |
| `git.branching_strategy` | `none`/`phase`/`milestone` | Git 브랜칭 전략 |

## gsd-tools.js: CLI 상태 관리 도구

`/get-shit-done/bin/gsd-tools.js` (1000+ 줄)는 모든 상태 관리를 담당한다:

### 상태 명령어

```bash
# 상태 로드
gsd-tools state load

# 상태 업데이트 (개별 필드)
gsd-tools state update current_phase 3
gsd-tools state update current_plan 2

# 배치 업데이트
gsd-tools state patch --current_phase 3 --current_plan 2 --current_task 1

# 결정 기록
gsd-tools state add-decision "PostgreSQL 사용" "ACID 필요"

# 블로커 기록/해결
gsd-tools state add-blocker "Stripe API 키 필요"
gsd-tools state resolve-blocker 1

# 메트릭 기록
gsd-tools state record-metric velocity 2.5
```

### Phase 명령어

```bash
# Phase 추가 (맨 뒤에)
gsd-tools phase add "알림 시스템"

# Phase 삽입 (1 뒤에)
gsd-tools phase insert 1 "이메일 인증"
# → Phase 1.1이 됨

# Phase 제거
gsd-tools phase remove 3 --force

# Phase 완료
gsd-tools phase complete 2
```

### 검증 명령어

```bash
# Plan 구조 검증
gsd-tools verify plan-structure .planning/phases/01/PLAN-01.md

# Phase 완료도 검증 (모든 Plan에 Summary 있는지)
gsd-tools verify phase-completeness 3

# 산출물 검증 (must_haves 파일 존재 확인)
gsd-tools verify artifacts .planning/phases/01/PLAN-01.md

# 커밋 검증
gsd-tools verify commits abc123 def456
```

### 템플릿/스캐폴딩 명령어

```bash
# CONTEXT.md 생성
gsd-tools scaffold context --phase 3

# UAT.md 생성
gsd-tools scaffold uat --phase 3

# SUMMARY.md 프리필
gsd-tools template fill summary --phase 3

# PLAN.md 프리필
gsd-tools template fill plan --phase 3
```

### Git 통합

```bash
# 원자적 커밋
gsd-tools commit "feat(03-01): 로그인 엔드포인트 구현" --files src/api/login.ts

# 진행률 표시
gsd-tools progress        # 기본 (텍스트)
gsd-tools progress bar    # 프로그레스 바
gsd-tools progress json   # JSON 형식
gsd-tools progress table  # 표 형식
```
