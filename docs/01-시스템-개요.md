# GSD (Get Shit Done) 시스템 개요

## 이 시스템은 무엇인가?

GSD는 **메타 프롬프팅 & 컨텍스트 엔지니어링 시스템**이다.
Claude Code(또는 OpenCode, Gemini CLI) 같은 AI 코딩 도구를 사용해 복잡한 애플리케이션을 안정적으로 구축할 수 있도록 설계되었다.

## 핵심 문제: Context Rot (컨텍스트 부패)

AI 모델은 대화가 길어질수록 품질이 저하된다:

```
컨텍스트 사용률    품질
0-30%             PEAK (최고)
30-50%            GOOD (양호)
50-70%            DEGRADING (저하)
70%+              POOR (불량)
```

GSD는 이 문제를 **독립적인 에이전트로 작업을 분할**하여 해결한다.
각 에이전트는 신선한 컨텍스트에서 시작하므로 항상 최고 품질을 유지한다.

## 핵심 철학

1. **Spec-Driven Development**: 코드 작성 전에 반드시 명세(스펙)를 먼저 작성
2. **Multi-Agent Orchestration**: 하나의 AI가 모든 것을 하는 대신 전문화된 에이전트들이 협업
3. **Atomic Commits**: 각 작업 = 하나의 독립된 커밋 (되돌리기 가능)
4. **Goal-Backward Verification**: 작업 완료를 신뢰하지 않고, 결과물을 검증
5. **Session Continuity**: 여러 세션에 걸쳐 프로젝트 상태를 유지

## 기술 스택

- **런타임**: Node.js >= 16.7.0
- **프로덕션 의존성**: 0개 (제로 디펜던시)
- **빌드 도구**: esbuild (훅 번들링용)
- **배포**: npm 패키지 (`get-shit-done-cc`)
- **지원 플랫폼**: macOS, Linux, Windows
- **지원 AI 런타임**: Claude Code, OpenCode, Gemini CLI

## 설치 방식

```bash
# 인터랙티브 (대화형)
npx get-shit-done-cc@latest

# Claude Code 전용, 글로벌 설치
npx get-shit-done-cc --claude --global

# 모든 런타임, 글로벌 설치
npx get-shit-done-cc --all --global

# 프로젝트 로컬 설치
npx get-shit-done-cc --local
```

## 핵심 워크플로우 (4단계)

```
[1] Describe (기술)     → /gsd:new-project
    무엇을 만들고 싶은지 정의

[2] Plan (계획)         → /gsd:plan-phase
    각 단계의 세부 실행 계획 수립

[3] Execute (실행)      → /gsd:execute-phase
    계획에 따라 코드 작성 및 커밋

[4] Verify (검증)       → /gsd:verify-work
    결과물이 목표를 달성했는지 검증
```

이 4단계 사이클이 GSD의 핵심이며, 모든 기능은 이 사이클을 지원하기 위해 존재한다.
