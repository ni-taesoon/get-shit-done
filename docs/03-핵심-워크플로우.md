## Phase 1: New Project (`/gsd:new-project`)

**워크플로우 파일**: `get-shit-done/workflows/new-project.md` (958줄)

### 실행 순서

1. **Deep Questioning (심층 질문)**
   - 사용자에게 프로젝트에 대한 질문을 하여 요구사항 수집
   - 무엇을 만들고 싶은지, 핵심 가치는 무엇인지 파악
   - `gsd-codebase-mapper` 에이전트로 기존 코드베이스 분석 (브라운필드)

2. **Optional Research (선택적 연구)**
   - `gsd-project-researcher` 에이전트가 도메인/기술 스택 조사
   - `.planning/research/` 에 연구 결과 저장

3. **Document Generation (문서 생성)**
   ```
   PROJECT.md       → 프로젝트 정의 (2-3문장)
   REQUIREMENTS.md  → v1/v2/Out-of-scope 요구사항
   ROADMAP.md       → Phase별 개발 계획
   config.json      → 워크플로우 설정
   STATE.md         → 초기 상태
   ```

### 핵심 원칙
- "What" (무엇)에 집중, "How" (어떻게)는 나중에
- v1 요구사항 = 반드시 필요한 것만
- Out-of-scope에 명확한 이유 기재

## Phase 2: Plan Phase (`/gsd:plan-phase`)

**워크플로우 파일**: `get-shit-done/workflows/plan-phase.md` (376줄)

### 실행 순서

1. **Phase Research (단계 연구)**
   - `gsd-phase-researcher`가 해당 phase의 기술적 조사 수행
   - RESEARCH.md 생성

2. **Plan Creation (계획 생성)**
   - `gsd-planner`가 PLAN.md 생성
   - 각 Plan에 2-3개 Task 포함
   - Task는 XML 구조로 정의

3. **Plan Verification (계획 검증)**
   - `gsd-plan-checker`가 계획이 phase 목표를 달성하는지 검증
   - 부족하면 planner에게 수정 요청

### PLAN.md 구조

```markdown
---
phase: 3
plan: 1
type: auto          # auto | tdd
wave: 1             # 병렬화 Wave 번호
depends_on: []      # 의존하는 Plan
---

## Objective
무엇을 왜 구현하는지

## Context
@PROJECT.md
@.planning/ROADMAP.md

## Tasks

<task type="auto">
  <name>로그인 엔드포인트 생성</name>
  <files>src/app/api/auth/login/route.ts</files>
  <action>
    POST /api/auth/login 엔드포인트를 구현한다.
    이메일과 비밀번호를 받아 JWT 토큰을 반환한다.
  </action>
  <verify>
    curl -X POST /api/auth/login -d '{"email":"test@test.com","password":"test"}'
    → 200 OK + JWT token 반환 확인
  </verify>
  <done>
    로그인 엔드포인트가 올바른 자격증명에 JWT를 반환함
  </done>
</task>

## Verification
- [ ] 모든 API 엔드포인트 응답 확인
- [ ] 잘못된 입력에 적절한 에러 반환
```

## Phase 3: Execute Phase (`/gsd:execute-phase`)

**워크플로우 파일**: `get-shit-done/workflows/execute-phase.md`

### Task 실행 프로토콜

각 Task마다:
1. Task 내용 읽기
2. 코드 구현
3. `<verify>` 섹션으로 동작 확인
4. `<done>` 조건 충족 확인
5. 원자적 커밋 (task 하나 = 커밋 하나)

### 커밋 형식

```
{type}({phase}-{plan}): {task-name}

- 주요 변경 1
- 주요 변경 2
- 주요 변경 3
```

**커밋 타입**: feat, fix, test, refactor, perf, chore

### Deviation Rules (이탈 규칙)

실행 중 예상치 못한 상황 발생 시:

| 규칙 | 상황 | 행동 |
|------|------|------|
| RULE 1 | 버그 발견 | 자동 수정 |
| RULE 2 | 필수 기능 누락 | 자동 추가 |
| RULE 3 | 스텁/플레이스홀더 발견 | 자동 제거 |
| RULE 4 | 비필수 추가 기능 | 사용자 승인 대기 |
| RULE 5 | 아키텍처 변경 필요 | 에스컬레이션 |

### TDD 실행 패턴 (type: tdd인 경우)

```
RED    → 실패하는 테스트 작성 + 커밋 ("test(phase-plan): ...")
GREEN  → 테스트 통과하는 구현 + 커밋 ("feat(phase-plan): ...")
REFACTOR → 코드 정리 + 커밋 ("refactor(phase-plan): ...")
```

## Phase 4: Verify Work (`/gsd:verify-work`)

**워크플로우 파일**: `get-shit-done/workflows/verify-work.md` (570줄)

### Goal-Backward Verification (목표 역추적 검증)

Task 완료를 신뢰하지 않고, **결과물로부터 역추적**하여 검증:

```
Level 4: FUNCTIONAL (기능적)
  └── 실제로 호출하면 작동하는가?

Level 3: WIRED (연결됨)
  └── 시스템의 나머지 부분과 연결되어 있는가?

Level 2: SUBSTANTIVE (실체적)
  └── 내용이 실제인가? (스텁/플레이스홀더가 아닌가?)

Level 1: EXISTS (존재)
  └── 파일이 예상 경로에 있는가?
```

### Stub Detection (스텁 감지)

GSD는 정규식 패턴으로 가짜 구현을 자동 감지한다:

```
TODO, FIXME, PLACEHOLDER
"not yet implemented"
"coming soon"
console.log("stub")
pass  # Python의 빈 함수
throw new Error("Not implemented")
```

### Gap 발견 시 자동 복구

```
VERIFICATION.md에서 Gap 발견
    │
    ▼
자동으로 수정 PLAN.md 생성
    │
    ▼
Executor가 수정 Plan 실행
    │
    ▼
재검증 (최적화: 이미 통과한 항목은 스킵)
```

## Checkpoint System (체크포인트)

실행 중 일시정지가 필요한 3가지 유형:

### 1. checkpoint:human-verify (90%)
```markdown
<checkpoint type="human-verify">
  브라우저에서 /login 페이지를 열고:
  1. 이메일과 비밀번호를 입력
  2. 로그인 버튼 클릭
  3. 대시보드로 리다이렉트 확인
  4. UI가 디자인과 일치하는지 확인
</checkpoint>
```

### 2. checkpoint:decision (9%)
```markdown
<checkpoint type="decision">
  인증 방식을 선택해주세요:
  A) JWT + 쿠키 (서버사이드 렌더링에 적합)
  B) JWT + 로컬스토리지 (SPA에 적합)
  C) 세션 기반 (전통적, 간단)
</checkpoint>
```

### 3. checkpoint:manual (1%)
```markdown
<checkpoint type="manual">
  Stripe 대시보드에서 API 키를 생성하고
  .env 파일에 STRIPE_SECRET_KEY를 추가해주세요.
</checkpoint>
```

## 세션 관리

### 작업 일시정지 (`/gsd:pause-work`)
```
.planning/.continue-here.md 생성
  ├── 완료된 Task 목록 (커밋 해시 포함)
  ├── 현재 위치 (Phase X, Plan Y, Task Z)
  ├── 다음 할 일
  └── 체크포인트 상태
```

### 작업 재개 (`/gsd:resume-work`)
```
.continue-here.md 읽기
  → STATE.md 복원
  → 정확한 중단 지점에서 재개
```
